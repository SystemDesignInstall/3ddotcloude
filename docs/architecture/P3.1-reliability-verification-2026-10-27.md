Изменения исполнения опираются на ратифицированный RFC-0003 и ADR-014/020/022.

## Направление проекта

Цель — постоянная пространственная сцена, объединяющая фото, траектории SLAM,
LiDAR и измерительные ограничения. Наблюдения, координатные системы и происхождение
данных принадлежат платформе; COLMAP, GTSAM и будущие алгоритмы подключаются через
заменяемые адаптеры. Ближайший практический результат — проверенная реконструкция
на реальных фото и затем её совмещение с метрической траекторией SLAM.

Изучены приложенная `SP-ARCH-MATRIX-0001`, product blueprint, Constitution,
актуальные решения управления архитектурой, история Git, исходный код исполнения,
адаптеров и тестов. Полный архив старых чатов получить не удалось: поиск Personal
Context вернул недоступность. Доступная сводка обсуждений использована как ориентир;
текущее состояние определялось по коду и проверкам. Другие проекты пользователя
в эту работу не включены.

Матрица от 2026-08-10 содержит исследовательские направления и устаревшую нумерацию
этапов. Для текущего исполнения приоритет имеют ратифицированные RFC и реализованные
контракты. AI остаётся последующим направлением.

## Реализованный инкремент

1. **Правильная классификация ошибок.** `InProcessExecutor` переводит `ProjectError`
   в событие с исходным стабильным кодом, сообщением и `recoverable`. Ошибка входа
   или отказ D5 больше не объявляется временным `WORKER_CRASHED`. Неразмеченные
   исключения сохраняют прежний путь сбоя worker. Регрессии проверяют события,
   реальные вызовы через Engine, сохранённые попытки и отказ D5 через
   `Engine::RunPipeline`.
   CLI сохраняет JSON manifest на stdout и выводит исходную причину отказа со
   стабильным кодом на stderr; отдельная CLI E2E проверяет этот диагностический путь.
   Терминальное событие публикуется после выхода runner и освобождения worker:
   следующий Submit больше не пересекается с завершением предыдущей задачи.
   Проверка синхронизации не использует задержки для имитации гонки.
2. **Достоверный cache telemetry.** Пропущенный этап без `task_runs` больше не
   отмечается `cache_hit=true`; failed/skipped этапы не публикуют placeholder как
   ссылку на готовый артефакт. Проверяется также повторно загруженный manifest.
   N3 отдельно подтверждает реальное audit evidence через CAS и соответствующую DB запись.
3. **Время жизни CLI providers.** Engine уничтожается и присоединяет свой worker
   раньше освобождения объектов, захваченных runner по указателям.
4. **Изоляция тестовых данных.** 47 выражений `time(seconds) + rand()` заменены
   UUIDv4. Раздельные процессы GTest больше не выбирают одинаковые каталоги из-за
   одинакового начального состояния `rand()` и запуска в одну секунду.
5. **Исполняемая сборка Linux.** Добавлены GCC 13 / Ninja профили и Debug/Release
   presets. MSVC flags и копирование DLL ограничены подходящей платформой;
   Windows test presets явно выбирают конфигурацию. CLI также учитывает отключённый
   GTSAM adapter при компиляции.
6. **Реальные CI jobs.** Вместо вывода сообщения-заглушки настроены Conan install,
   configure, build и CTest для Ubuntu / Windows × Debug / Release. Исправлен адрес
   governance checkout. Из CI удалены фиктивные проверки отсутствующего Python SDK.

Публичные схемы, миграции, математические реализации 8a/8b/8c и алгоритмы оптимизации
не менялись. Linux использует stable serial GTSAM без optional TBB/METIS/unstable
модулей. Сам GTSAM 4.2.1 собирается GCC в C++17 из-за несовместимых с
C++20 конструкторов во встроенной Spectra; платформа и адаптеры остаются C++20.
Исходники зависимости не правились. Windows profiles сохраняют прежние options. Межплатформенная побитовая
тождественность численных результатов не заявляется.

## Открытые условия production acceptance

1. **Подтверждение метрического масштаба.** Runner разбирает `metric.trajectory`
   из run config. `ValidateMetricBasis` проверяет заполненность
   `scale_calibration_ref` и `provenance.configuration_hash`, но не удостоверяет
   источник физического масштаба. Само наличие строки или CAS hash не доказывает
   метры. Нужен контракт импортированного/вычисленного метрического свидетельства,
   проверка его lineage, frame и единиц на host boundary.
2. **Native COLMAP и реальные данные.** Требуются сохранённый набор фото, версии
   инструментов, калибровка, воспроизводимый запуск и независимые метрики качества.
   Синтетическая геометрия и protocol probe этого не заменяют.
3. **Recovery / publication.** Нужен полный перечень сбоев между CAS publication,
   записью domain revision и supersede, включая restart. Текущий инкремент устраняет
   ошибочные повторы постоянных ошибок, но не объявляет все host stages идемпотентными.
4. **Свежая полная матрица и sanitizers.** Результаты каждой платформы должны быть
   получены отдельно. ASan/UBSan из ADR-016 остаются отдельным незакрытым пунктом;
   обычная Debug сборка не является sanitizer run.

Следующий предметный инкремент: доверенный импорт метрической траектории и
её evidence, затем фото + SLAM на одной реальной сцене с проверяемыми frame joins,
масштабом, исходной/исправленной траекторией и измеренными остатками.
