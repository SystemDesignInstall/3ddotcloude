# Импорт результатов A2 mapper

Статус: реализован в настольном исследовательском приложении Spatial Photo Cloud.
Импорт в Core / `.spx`, исправление траекторий и обработка сырых `.bag`/`.bin`
этим изменением не реализуются. Код A2 mapper не используется.

## Как открыть съёмку

1. Обработать запись в установленном отдельно A2 mapper.
2. В Spatial Photo Cloud нажать **Импорт съёмки A2 mapper…**.
3. Выбрать папку с `cloud.las` и `trajectory.txt`, затем папку для результата.
4. При необходимости выбрать CSV опорных точек из другой папки.
5. Указать обозначение системы координат и известную версию производителя
   (либо оставить `unknown`). Выбор имени не подтверждает географическую привязку.
6. Выбрать RGB: стандартный 16-битный диапазон LAS либо явно известный 8-битный
   экспорт; вертикаль для просмотра — Z или Y. Координаты при этом не меняются.
7. Нажать **Импортировать съёмку**. После импорта откроется локальный HTML-отчёт.
   Кнопка **Открыть построенное облако** открывает полный PLY в имеющемся viewer.

CSV автоматически ищется только рядом с LAS. Приоритет:
`ctrl_points_edit.csv`, затем `control_points.csv`, затем единственный `*.gcp.csv`.
При нескольких A2 CSV требуется явный выбор. Вложенные папки и соседние сессии
автоматически не объединяются.

Исходники не заменяются. Для каждого запуска создаётся новая папка:

```text
a2-capture-<id>/
  cloud.ply                    # рабочая копия для просмотра/выравнивания
  capture/
    sources/cloud.las          # точная копия со всеми LAS-атрибутами
    sources/trajectory.txt     # точная копия исходной траектории
    sources/control_points.csv # выбранный CSV, если есть
    configuration.json         # явные параметры импорта
    trajectory.jsonl           # все позы, время int64 ns
    control_points.json        # принятые/отклонённые строки и причины
    report.html                # маршрут XY, статистика и опоры
    manifest.json              # commit marker, provenance и SHA-256
```

Файлы `capture/` не редактируются импортёром после публикации. Изменения в viewer
относятся только к рабочему `cloud.ply`; они не исправляют и не перемещают траекторию,
CSV или исходный LAS. Совместное редактирование всей сессии ещё не поддерживается.
Отсутствие `manifest.json` означает незавершённый импорт. Отмена и обработанные
ошибки удаляют только созданную этим запуском папку. После принудительного
завершения процесса/сбоя питания может остаться неполная папка без manifest;
автоматического восстановления после такого сбоя нет.

## CLI

```sh
python python/research/photo_to_cloud/a2_import.py \
  --input /data/a2-export --output /data/new-capture \
  --coordinate-frame survey_local_unverified --source-version v4 \
  --controls /data/scan/ctrl_points_edit.csv --rgb-encoding uint16 --up-axis z
```

В собранной программе тот же интерфейс доступен через
`SpatialPhotoCloud.exe --a2-import-worker ...`.
Коды возврата: `0` — импорт, `1` — ошибка, `130` — отмена.
`--cancel-file` — путь к сигналу отмены. Выходная папка не должна существовать.
Для запуска импортёра отдельно нужны Python, NumPy и `laspy==2.6.1`; GUI также Tk.

## Проверки данных и границы

- LAS читается частями по 100 000 точек. Все точки экспортируются; координаты PLY
  имеют float64, поэтому нет потери миллиметров из-за раннего преобразования больших
  координат в float32. Viewer всё ещё должен вместить облако в память браузера.
- Цвет PLY 8-битный: для стандартного LAS `(value + 128) // 257`; явный режим uint8
  отклоняет значения выше 255. Автоматически угадывать глубину по тёмному облаку нельзя.
- Нецветное облако отображается серым. LAS-классификация, интенсивность, GPS time,
  нормали/дополнительные поля и CRS сохраняются в исходном LAS, не в display PLY.
- Проверяются размер данных, число точек, конечность координат, положительные scales.
  LAZ отвергается. Реальные A2-экспорты всех LAS-версий ещё не испытаны.
- Траектория: ровно 11 полей `x y z roll pitch yaw qx qy qz qw timestamp`.
  Время переводится Decimal-арифметикой в наносекунды без округления. Неупорядоченное,
  отрицательное, повторяющееся время и дробные наносекунды отклоняются.
- Quaternion с отклонением нормы не более 0,001 нормализуется в производном JSONL;
  исходный TXT сохраняется. RPY остаётся исходным: порядок вращений неизвестен.
- Положение оптического центра камеры не выводится из позы сканера. Нельзя подавать
  полученные позы в `ImportTumCameraTrajectory` без определения исходного frame,
  калибровки sensor-to-camera и синхронизации времени.
- SHARE CSV: регистр столбцов не важен; пустые/нечисловые координаты записываются
  в список отказов, а не исчезают молча. Дополнительные именованные колонки игнорируются.
- A2 RTK CSV: принимаются только строки с явным `carr_soln=2`. При отсутствии статуса
  RTK fixed не предполагается. Геодезические координаты и эллипсоидальная высота
  сохраняются без выдуманного ENU-origin или преобразования в неизвестный datum.
- Опоры получают `role=unassigned`; коррекция и независимые checkpoints не смешиваются.
  Попадание timestamp в диапазон траектории — диагностический факт, не синхронизация.
- Отчёт показывает длину пути и расстояние между концами, не RMSE точности.
  Предпросмотр XY ограничен первыми 2000 позами; полный JSONL сохраняет весь маршрут.
- Числа LAS и траектории считаются метрами согласно документированному экспорту A2,
  но `metric_accuracy`, CRS и clock sync остаются `unverified`.
- Текстовые файлы TXT/CSV ограничены 128 МиБ; бинарный LAS не загружается целиком.

## Источники и лицензии

Документированный формат проверен по A2 mapper v4, commit
[`5212867f9fb7198d55f0a08f72aa0f381c11fa67`](https://github.com/Werdna0107/A2-slam/tree/5212867f9fb7198d55f0a08f72aa0f381c11fa67).
Бинарники A2 не включены, не скачиваются и не запускаются. Это собственная реализация
чтения опубликованных форматов. LAS обрабатывается laspy (BSD-2-Clause), текст лицензии
включён в пакет. Версия производителя, введённая пользователем, не удостоверяет источник.

Полная программа развития и условия интеграции в Core:
[A2 mapper — integration and evaluation](../architecture/A2-mapper-integration.md).
