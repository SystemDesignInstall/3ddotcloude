## 1. Outcome

P2.1 delivers the first real vertical slice of the Permanent Spatial Data Model:
an image file is ingested byte-exactly into an immutable **ImageArtifact** (CAS),
a **Frame**, and an **ImageObservation**, all inside a **CaptureSession**, with
deterministic v5 identity, full provenance, content-addressed deduplication, and
per-file failure semantics.

```
Image → Import → CAS Artifact → Frame → ImageObservation → CaptureSession
```

End-to-end verified through the `spatial import` CLI: import produces the three
canonical records; a re-import of the identical tuple reports `reimported: true`
and writes nothing (dedup case 1); byte-exact fidelity, session membership, and
observation provenance are asserted by tests.

## 5. Adapter boundary

`importers/images/**` includes only: `core/*` headers, stdlib, and
`<nlohmann/json.hpp>` (an active M0 dependency used for canonical JSON
serialization, not a vendor image type). No Eigen, protobuf, or image decoder
appears; OpenCV/FFmpeg are `planned` in `THIRD_PARTY.yml`, never `active`.
`target_link_libraries(spatial_importers PUBLIC spatial_core)` — nothing else.
No vendor type or foreign field leaks into the Canonical Spatial Model (§16.11).

## 6. Provenance chain

- **ImageArtifact:** `producer {id: image-import, version, git_commit}`,
  `configuration_hash`, `creation_timestamp`, `input_artifact_hashes: []`,
  `width/height/pixel_format`, `mime_type`, `validation_status: "valid"`.
  (`source_uri`/mtime — see #6.)
- **Frame / ImageObservation:** `source` (importer id/version/git_commit),
  `properties` (`configuration_hash`), `artifact_ref` links the ImageArtifact —
  chain `bytes → artifact → observation → frame` complete.
- **CaptureSession:** `source_uri`, `provenance_json`.
- **Scene / SceneVersion:** `created_by` (importer provenance), stage `imported`
  (ADR-033 chain).

## 7. API surface for the next Capability

Write side is complete: `InsertFrame`/`InsertObservation`/`InsertObservationPayload`,
`FindOrCreateScene`/`CreateSceneVersion`, `InsertCaptureSession`, `FindSession`,
`FindSensor` (+`has_calibration`), `FrameExists`/`ObservationExists`,
`Put`/`PutInstance`, `FindArtifactsByType`.

Read side is thin: there are no typed accessors to list frames/observations of a
session or read a `FrameRow`/`ObservationRow` back out. A downstream Capability
(SfM/COLMAP) currently reads through raw `sqlite3*` (`MetadataDb::db()`). The
typed scene read surface is the entry point for the next Capability and is
tracked as #9 (ADR-035).

## 9. Technical debt

### #5 Stale working-tree file — housekeeping, not architectural

`importers/images/image_importer.cpp` is a stale untracked duplicate of
`image_importer_main.cpp` held by an external file handle. Not committed, not
built, no impact on status. Delete after the handle is released:
`del importers\images\image_importer.cpp`, then verify `git status`.

### #7 JSON Schema validation of produced manifests — CLOSED (`3d5b9ea`)

Acceptance §16.8 requires that all ImageArtifacts validate against
`image.schema.json`. `test_image_importer.cpp` now carries a self-contained
conformance check that reads the exact on-disk manifest (`artifacts/<uuid>/manifest.json`)
produced by a real import and validates it against
`schemas/json/image.schema.json` — covering the keywords the schema uses
(`required`, `type`, `const`, `enum`, `pattern`, `minimum`, array `items`).
The schema path is injected via `SPATIAL_IMAGE_SCHEMA_JSON` (mirroring
`SPATIAL_QUALITY_SCHEMA_JSON`). No third-party validator was added; the
`format` keywords (uuid / date-time) are intentionally not enforced beyond the
string type. Test: `ProducedManifestValidatesAgainstImageSchema`.

### #8 Rejected-file provenance — CLOSED (`3d5b9ea`)

`image-import.md` §14 requires the rejection to be recorded with provenance
(path, mime, importer version). Migration `0005_import_rejections.sql` adds the
`import_rejections` table: `rejection_id`, `project_id`, `session_id`
(batch-linked), `sequence_index`, `source_path`, `mime_type` (detected MIME
when the header parsed, else empty), `importer` / `importer_version`,
`error_code` (stable `IMPORT_*` name), `diagnostic`, `rejected_at_ns`. The
importer writes one row per per-file failure via
`ImageImporter::RecordRejection`; a rejected input never writes an artifact,
frame, or observation. Typed accessors `InsertImportRejection` /
`FindImportRejectionsBySession` added to `MetadataDb`. Tests:
`RejectedInputsLeavePersistentProvenance`, plus MIME provenance asserted in
`SensorUnresolvedFails`.

### #6 `source_uri` + mtime in artifact provenance — follow-up

`image-import.md` §11 mentions source_uri + source mtime in the artifact
provenance block; the manifest does not carry it (lineage is resolvable today
via `capture_sessions.source_uri`). Decision deferred: first settle what the
canonical source metadata is (manifest provenance block vs. session record),
then reconcile the contract — do not silently compensate via the DB.

### #9 Scene Query API — follow-up → ADR-035

Typed scene reads (`FindFramesBySession`, `GetObservation`, …) are out of P2.1
scope and become the entrance to the next Capability under ADR-035.

## 11. Decisions carried into the next Capability

- **Sensor/calibration registration is P2.2.** Calibration resolution is
  presence-based (`has_calibration`); validity-interval-aware resolution needs
  registration columns (migration-0001 has none). Flagged `uncalibrated` is a
  warning, never a failure.
- **EXIF extraction deferred.** The schema reserves the `exif` object; the
  importer records metadata *as available* (none today). Full EXIF is a later
  increment.
- **IMPORT error codes are stable.** `IMPORT_UNREADABLE` … `IMPORT_VALIDATION_ERROR`
  (domain 6) are the machine-readable contract for importer failures.
- **Rejected inputs persist, never partial-write.** Every per-file failure writes
  one `import_rejections` row (migration 0005) and nothing else — no artifact,
  frame, or observation. New importer families (LiDAR, video, GNSS) reuse the
  same rejection provenance surface.
- **Dedup semantics fixed:** case 1 (context-identical → idempotent, no writes),
  case 2 (content-identical, context-different → one CAS payload, new instance).
- **Identity is content-derived:** `UUIDv5(ns, "<prefix>|<sensor_id>|<timestamp_ns>|<content_hash>")`.
  New importer families (LiDAR, video, GNSS) reuse the same primitive.
