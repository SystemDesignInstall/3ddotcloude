## 1. Scope boundary (ADR-035)

P2.2-B implements a **minimal typed read subset** of ADR-035's full `scene.query()` surface. In scope: typed, read-only Frame/Observation queries by session/sensor/time-range, Session->Scene traversal, Scene/version metadata reads, and exposure of calibration resolution. The query surface returns strict domain types (`core::scene::Frame`, `ImageObservation`, `CaptureSession`, `Scene`, `SceneVersion`, `Sensor`) — never raw rows, never SQL, never raw storage internals. Mutation stays behind the versioned write path; the query API is read-only.

**Out of scope (post-M0 per ADR-035):** `.lidar()`, `.points()`, `.visibleFrom(camera)` (geometry-graph joins), `.quality()`, `.uncertainty()` (channels), spatial-index-accelerated queries, and any write/mutation surface.

## 2. Existing-schema audit (migration `0001`, schema-resident)

| Table | Findings |
|---|---|
| `sensors` | `calibration_id` is a single scalar "current" pointer; no validity columns; no `SensorHealth`/`Device` (RFC-0002 §6.4, deferred). |
| `calibrations` | `calibration_time_ns` is a production time, **not** a validity window; `valid_from`/`valid_to` (sensor-model.md §3.1) unimplemented; `source` is plain string. JSON schema mirrors the gap. |
| `frames` / `observations` | No `calibration_id`; resolution derived at read time (append-only calibrations make it deterministic). |
| `capture_sessions` | No rig link (deferrable, out of scope). |
| Accessors | `FindSensor` returns `has_calibration` = EXISTS (presence, not interval). No `RegisterSensor`, `AddCalibration`, `ResolveCalibrationAt`, `FindFrames`, `FindObservations` typed accessors exist. |

Importer gap (`importers/images/image_importer.cpp`): `sensor_unresolved` = error; `uncalibrated = !has_calibration` = warning. RFC-0006 §9 already ratifies "calibration valid at capture time" resolution; P2.2 completes that ratified contract.

## 3. Validity-interval semantics

Resolution uses **half-open intervals**:

```
valid_from_ns <= timestamp_ns < valid_to_ns
```

- `valid_from_ns` is **always required** and inclusive.
- `valid_to_ns` is optional. When present it is **exclusive** (`timestamp_ns == valid_to_ns` does NOT match).
- Open-ended calibration (no upper bound):

```
valid_to_ns IS NULL
```

matches any `timestamp_ns >= valid_from_ns`.
- Ordering is enforced: `valid_from_ns < valid_to_ns` when `valid_to_ns` is present.
- At most one calibration is valid per sensor per timestamp (half-open intervals never overlap at a boundary).
- A timestamp in a gap, before the first interval, or at/after an interval's `valid_to_ns` resolves to `nullopt` — never a guess. The importer maps `nullopt` to the existing `kImportCalibrationMissing` **warning** (RFC-0006: warning, not a failure).
- Backfill: pre-existing rows (no validity columns) get `valid_from_ns = calibration_time_ns`, `valid_to_ns = NULL` (open-ended), so all legacy calibrations resolve.

**Critical rule:**

> `sensors.calibration_id` MUST NOT participate in historical calibration resolution.

The scalar pointer is a maintained "latest calibration" convenience only; resolution reads the `calibrations` table intervals exclusively.

## 4. Sensor registration contract

- **Create** — `RegisterSensor`: new `sensor_id`; duplicate rejected (PK); identity immutable; `source` = `ProducerInfo` (app + version + git commit).
- **Update** — two verbs (sensor-model.md §1, invariant 6):
  - `UpdateSensorMetadata`: non-identity attributes only (`manufacturer`, `model`, `serial_number`, `status`, `rig_id`); `sensor_id` never mutated in place.
  - `AddCalibration`: append-only; `version` = previous + 1; new validity interval; history never rewritten.
- **Resolve** — `ResolveSensor(id)`; `ResolveCalibrationAt(sensor_id, timestamp_ns)` per §3 semantics. On `AddCalibration`, `sensors.calibration_id` is updated to the newest calibration (latest-pointer), but resolution never reads it (§3 rule).

## 5. Minimal typed read API (P2.2 subset)

SQL stays in `core/storage/` (not Constitution-protected); `core/scene/query/**` maps rows to typed domain structs:

- `Frames()`, `FramesBySession(session_id)`, `FramesBySensor(sensor_id)`, `FramesInTimeRange(t0, t1)`
- `Observations()`, `ObservationsByFrame(frame_id)`, `ObservationsBySession(session_id)`, `ObservationsBySensor(sensor_id)`, `ObservationsInTimeRange(t0, t1)`
- `SessionScene(session_id)` (session->scene traversal), Scene/Version/CaptureSession/Sensor reads
- `ResolveCalibrationAt(sensor_id, timestamp_ns)` exposed through the query surface

## 6. Migration strategy (truly minimal)

Single additive migration `0006_sensor_calibration_validity.sql`:

- `ALTER TABLE calibrations ADD COLUMN valid_from_ns INTEGER;`
- `ALTER TABLE calibrations ADD COLUMN valid_to_ns INTEGER;`
- Backfill per §3: `valid_from_ns = calibration_time_ns`, `valid_to_ns = NULL`.
- `calibration.schema.json`: add optional `valid_from_ns` / `valid_to_ns`.
- `sensors.calibration_id`: kept, maintained as latest-pointer by `AddCalibration`; never used for resolution.
- **No** new tables (`sensor_versions`, `scene_sensor`); **no** `frames`/`observations` column changes; no Device/SensorHealth.
