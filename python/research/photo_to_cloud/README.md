# Photo Cloud — экспериментальный запуск

Небольшая локальная программа для первой проверки сценария «папка фотографий → облако PLY».
Исходные фотографии остаются на компьютере. Это отдельный исследовательский прототип,
а не готовый продукт Spatial Platform: он пока не использует `.spx`, Scene, реестр
артефактов или SLAM и не имеет встроенного 3D-просмотрщика.

## Что требуется

- 64-битный Python 3.11, 3.12 или 3.13 с Tkinter и интернет для первоначальной установки пакетов. Для новой установки рекомендуем Python 3.13.
- Для плотного облака на CPU: [OpenMVS 2.4.0](https://github.com/cdcseacave/openMVS/releases/tag/v2.4.0), **обычный архив без CUDA**, распакованный отдельно. На Windows выбрать `OpenMVS_Windows_x64.zip`; необходимые `.exe` находятся в `vc17/x64/Release`. На Linux выбрать `OpenMVS_Ubuntu_x64.zip` и убедиться, что `InterfaceCOLMAP` и `DensifyPointCloud` запускаются.
- Для просмотра `.ply` можно использовать [CloudCompare](https://www.cloudcompare.org/).

COLMAP здесь используется через официальный `pycolmap` 4.2.1. Определение ключевых
точек, сопоставление фотографий и расчёт камер выполняются на CPU. OpenMVS
строит плотное облако тоже на CPU, поэтому этот вариант работает на компьютере
с видеокартой AMD, но не использует её для ускорения.

OpenMVS распространяется по AGPL-3.0. Он не включён в этот репозиторий; перед
поставкой или коммерческим использованием интеграции нужен отдельный разбор
лицензии, как указано в `THIRD_PARTY.yml`.

## Установка и запуск на Windows

Скачайте репозиторий с веткой `codex/photo-cloud-mvp`, затем откройте PowerShell в
папке репозитория. С установленным Python 3.11–3.13 можно также дважды нажать
`python/research/photo_to_cloud/start-windows.bat`: при первом запуске скрипт
создаст окружение и скачает зависимости.

Для ручного запуска из PowerShell:

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r python\research\photo_to_cloud\requirements.txt
.\.venv\Scripts\python.exe python\research\photo_to_cloud\app.py
```

Если установлен Python 3.11 или 3.12, в первой строке замените `-3.13` на нужную версию.
На Linux аналогично используйте `python3 -m venv .venv`,
`.venv/bin/python -m pip install -r python/research/photo_to_cloud/requirements.txt`
и `.venv/bin/python python/research/photo_to_cloud/app.py`. Для Tkinter может
понадобиться системный пакет `python3-tk`.

В окне:

1. Выберите папку с JPG, PNG или TIFF и папку, где разместить результат.
2. Выберите «Плотное облако — CPU», затем папку, где находятся обе программы OpenMVS.
3. Нажмите «Построить облако». Программа создаст новую папку и покажет ход работы.
4. Откройте папку результата; `dense.ply` можно открыть в CloudCompare.

Режим «Разреженное облако — CPU» обходится без OpenMVS и создаёт `sparse.ply`.
Это точки, найденные при совмещении кадров, а не плотная поверхность объекта.
При сбое плотного этапа `sparse.ply` может остаться в папке, но полный запуск
будет помечен как неуспешный в `report.json`. Результат получает произвольный
масштаб: одних фотографий недостаточно для подтверждения размеров в метрах.
Если сцена разбилась на несколько моделей, экспортируется самая крупная по
числу зарегистрированных камер, а в журнале появляется предупреждение.

Один запуск создаёт новую папку с временной базой COLMAP, промежуточными данными,
облаком и `report.json`. Существующие папки не перезаписываются. Диск, память и
время зависят от количества и размера снимков; плотная обработка CPU может быть
медленной. Исходные файлы не копируются в проект: для повторной обработки их
нужно сохранить на прежнем месте.

## AMD GPU: эксперимент

COLMAP 4.2.0 добавил построение карт глубины на совместимых GPU AMD через HIP/ROCm.
Для режима «Плотное облако — AMD HIP» необходим **отдельно собранный COLMAP с
HIP**, совместимый с установленными драйвером, ОС и моделью карты. Стандартный
пакет `pycolmap` из `requirements.txt` работает на CPU и сам по себе HIP не
добавляет; стандартный Windows-архив COLMAP без CUDA также не является HIP-сборкой.
Инструкция по сборке: [COLMAP: Installation](https://colmap.github.io/install.html).

Этот режим вызывает `patch_match_stereo` и `stereo_fusion` внешней программы
COLMAP после CPU-этапа. Он **не проверен на реальном AMD GPU**; не заявляется
совместимость с конкретной картой или Windows-сборкой. Обычный CPU-режим остаётся
отдельным вариантом. Не подменяйте исходную сборку произвольным сторонним бинарным
файлом без проверки источника и совместимости.

## Фотографии

Для первого опыта снимите один неподвижный объект или небольшую комнату с разных
положений камеры, обеспечив сильное перекрытие соседних кадров. Избегайте
бликов, стекла, однотонных стен, смаза и резкой смены освещения. Успех зависит от
съёмки; даже корректный запуск может не найти достаточно общих точек.

## Командная строка

Новая папка результата должна находиться вне папки фотографий:

```sh
python python/research/photo_to_cloud/reconstruct.py --images /path/to/photos --output /path/to/new-result --mode sparse-cpu
python python/research/photo_to_cloud/reconstruct.py --images /path/to/photos --output /path/to/new-result --mode dense-cpu --openmvs-dir /path/to/openmvs
```

Для исследования HIP можно выбрать `--mode dense-amd --colmap /path/to/hip/colmap`.
Ошибки возвращают ненулевой код; проверяйте журнал и `report.json`.
