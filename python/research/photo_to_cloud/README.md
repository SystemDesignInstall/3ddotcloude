# Photo Cloud — экспериментальный запуск

Небольшая локальная программа для первой проверки сценария «папка фотографий → облако PLY».
Исходные фотографии остаются на компьютере. Это отдельный исследовательский прототип,
а не готовый продукт Spatial Platform: он пока не использует `.spx`, Scene, реестр
артефактов или SLAM. После обработки создаётся автономный HTML-просмотр выборки
точек, а полный результат остаётся в PLY.

## Тестовый комплект Windows

Workflow `Photo Cloud Windows test package` собирает архив `SpatialPhotoCloud-Windows-AMD-experiment`
с исполняемым файлом, Python и библиотеками внутри. Распакуйте архив целиком и
запустите `SpatialPhotoCloud.exe`; отдельно устанавливать Python не нужно.
Кнопка «Установить OpenMVS» скачивает официальный архив OpenMVS 2.4.0 (22 МБ),
проверяет фиксированный SHA-256 и устанавливает его отдельно в профиль пользователя.
Кнопка «Открыть построенное облако» открывает полный результат сразу после
обработки, без повторного выбора файла. «Открыть готовый PLY…» открывает облако,
построенное ранее, без обработки фотографий. На Windows программа использует
отдельное окно установленного Edge или Chrome; если они не найдены, используется
браузер по умолчанию. Окно и полное облако работают локально через адрес
`127.0.0.1`: облако не отправляется в интернет. Локальный просмотр доступен,
пока открыта программа; после её закрытия повторное обновление окна не сработает.
Количество видимых пикселей зависит от ракурса и перекрытия точек. Исходный PLY
изменяется только по кнопке сохранения. Для автономного просмотра без программы можно открыть отдельно
`full_viewer.html` и выбрать PLY вручную.

В полном просмотрщике:

- «Обзор» вращает облако мышью, Shift с мышью перемещает вид, колесо меняет масштаб.
  Исправлено зеркальное отображение, вызванное преобразованием камеры просмотрщика;
  сами координаты исходного файла при отображении не меняются.
- «Полёт» включает перспективу изнутри. W/S — вперёд и назад, A/D — влево и
  вправо, Q/E — вниз и вверх, Shift ускоряет движение. Мышь поворачивает камеру;
  если браузер не разрешает захват мыши, поворачивайте с зажатой левой кнопкой.
  Колесо и ползунок меняют скорость. «Обзор» возвращает прежний общий вид.
- «Масштаб и измерение»: увеличьте характерный участок, нажмите на две видимые
  точки и введите известное расстояние между ними в м, см или мм. После
  «Применить масштаб» можно выбрать другую пару для проверки её расстояния.
  «Сохранить в этот PLY» записывает масштаб в открытый файл; «Подготовить PLY
  в метрах», затем «Скачать PLY в метрах» создаёт отдельную копию. При импорте
  в другую программу укажите метры. Для координат целого
  типа экспорт не поддерживается — исходный файл в этом случае не меняется.
- «Выровнять облако»: поверните геометрию ползунками по осям X/Y/Z или кнопками
  на 90°. Для точной настройки введите угол в поле рядом с ползунком (до 0,01°),
  либо выберите шаг 1°, 0,1° или 0,01° и используйте кнопки −/+ или стрелки
  вверх/вниз в поле угла. Допустимы точка и запятая. Кнопки «Вид спереди» и «Вид сверху» и сетка помогают проверить пол и
  стены. Мышь по-прежнему меняет только ракурс, не поворачивая исходный объект.
  При сохранении выберите Y вверх или Z вверх для CAD. «Сохранить положение в этот
  PLY» записывает поворот, ось и заданный масштаб в тот же файл. Координаты и
  полные нормали точек поворачиваются вместе. Если масштаб не задан, остаются
  исходные произвольные единицы. Отдельный PLY также можно подготовить и скачать.

Перед изменением исходного файла приложение автоматически сохраняет его копию в
папку `.SpatialPhotoCloud-backups` рядом с PLY, затем проверяет результат и
заменяет исходный файл. Если PLY изменился в другой программе, сохранение будет
отклонено: откройте файл снова. На диске должно хватать места для временного файла
и резервной копии. Кнопка сохранения в исходный файл доступна для PLY, открытого
через окно программы; автономный HTML позволяет сохранить отдельную копию.

Масштаб задаётся равномерно по одной паре и хранится до закрытия или перезагрузки
просмотрщика, а после сохранения — в координатах PLY. В заголовок также добавляется
комментарий о единицах, чтобы при повторном открытии в этом просмотрщике можно
было сразу измерять расстояния в метрах. Масштаб и ручное выравнивание не устраняют
ошибки реконструкции и не задают географическую систему координат.
Для проверки точности полезно сравнить измерение с другим известным расстоянием.
Если окно чата не разрешает скачивание или захват мыши, скачайте HTML-просмотрщик
и откройте его локально в Edge или Chrome.
Кнопка «Остановить» запрашивает остановку вычислений; частичные файлы сохраняются,
а прерванный запуск не помечается как успешный.

Сборка проверяется в Windows CI на синтетических изображениях через сам упакованный
исполняемый файл. Реальные фотографии отдельно проверены в Linux; работа на
конкретном пользовательском компьютере и AMD GPU требует самостоятельной проверки.
Тестовый комплект не является коммерческим релизом: лицензии библиотек и состав
бинарных зависимостей требуют отдельного аудита перед поставкой.

## Что требуется

- 64-битный Python 3.11–3.14 с Tkinter и интернет для первоначальной установки пакетов. Для новой установки рекомендуем Python 3.14.
- Для плотного облака на CPU: [OpenMVS 2.4.0](https://github.com/cdcseacave/openMVS/releases/tag/v2.4.0), **обычный архив без CUDA**, распакованный отдельно. На Windows выбрать `OpenMVS_Windows_x64.zip`; необходимые `.exe` находятся в `vc17/x64/Release`. На Linux выбрать `OpenMVS_Ubuntu_x64.zip` и убедиться, что `InterfaceCOLMAP` и `DensifyPointCloud` запускаются.
- Для просмотра `.ply` можно использовать [CloudCompare](https://www.cloudcompare.org/).

COLMAP здесь используется через официальный `pycolmap` 4.2.1. Определение ключевых
точек, сопоставление фотографий и расчёт камер выполняются на CPU. OpenMVS
строит плотное облако тоже на CPU, поэтому этот вариант работает на компьютере
с видеокартой AMD, но не использует её для ускорения.

OpenMVS распространяется по AGPL-3.0. Он не включён в этот репозиторий; перед
поставкой или коммерческим использованием интеграции нужен отдельный разбор
лицензии, как указано в `THIRD_PARTY.yml`.

## Установка и запуск на Windows

Скачайте репозиторий с веткой `main`, затем откройте PowerShell в
папке репозитория. С установленным Python 3.11–3.14 можно также дважды нажать
`python/research/photo_to_cloud/start-windows.bat`: при первом запуске скрипт
создаст окружение и скачает зависимости.

Для ручного запуска из PowerShell:

```powershell
py -3.14 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r python\research\photo_to_cloud\requirements.txt
.\.venv\Scripts\python.exe python\research\photo_to_cloud\app.py
```

Если установлен Python 3.11–3.13, в первой строке замените `-3.14` на нужную версию.
На Linux аналогично используйте `python3 -m venv .venv`,
`.venv/bin/python -m pip install -r python/research/photo_to_cloud/requirements.txt`
и `.venv/bin/python python/research/photo_to_cloud/app.py`. Для Tkinter может
понадобиться системный пакет `python3-tk`.

В окне:

1. Выберите папку с CR2, JPG, PNG или TIFF и папку, где разместить результат.
2. Выберите «Плотное облако — CPU», затем папку, где находятся обе программы OpenMVS.
3. Нажмите «Построить облако». Программа создаст новую папку и покажет ход работы.
4. Нажмите «Просмотр» или откройте папку результата; `dense.ply` можно открыть в CloudCompare.

Режим «Разреженное облако — CPU» обходится без OpenMVS и создаёт `sparse.ply`.
Это точки, найденные при совмещении кадров, а не плотная поверхность объекта.
При сбое плотного этапа `sparse.ply` может остаться в папке, но полный запуск
будет помечен как неуспешный в `report.json`. Результат получает произвольный
масштаб: одних фотографий недостаточно для подтверждения размеров в метрах.
Если сцена разбилась на несколько моделей, экспортируется самая крупная по
числу зарегистрированных камер, а в журнале появляется предупреждение.

Один запуск создаёт новую папку с временной базой COLMAP, промежуточными данными,
облаком и `report.json`. Существующие папки не перезаписываются. Диск, память и
время зависят от количества и размера снимков; плотная обработка CPU может быть
медленной. Если есть CR2, программа сохраняет подготовленные копии всех кадров в `prepared_images`;
исходные файлы не изменяются. Для обычных форматов копии не создаются.

## CR2 и OpenCL на Windows: отдельный эксперимент

CR2 разворачиваются на CPU через rawpy/LibRaw в локальные JPEG полного размера;
сохраняются доступные модель камеры, фокусное расстояние и нормализованная ориентация.
Оригиналы не изменяются. Кадры, данные карты и итоговый отчёт остаются локально.

Режим «Плотное облако — AMD OpenCL (эксперимент)» использует внешнюю установку
COLMAP-CL 1.5. Кнопка установки скачивает её отдельно по запросу пользователя.
Выбранная запись `gfx1100` проверяется небольшим ядром и передаётся в COLMAP-CL
явно; журнал движка должен подтвердить платформу, устройство и индекс. Успех
также требует непустого PLY. На компьютере пользователя малые тесты OpenCL уже
прошли; полная реконструкция и совместимость с конкретным набором CR2 остаются
непроверенными. Исходный код и лицензия COLMAP-CL не подтверждены, а LibRaw имеет
условия LGPL/CDDL; эта сборка не является коммерческим релизом.

## AMD HIP: эксперимент

COLMAP 4.2.0 добавил построение карт глубины на совместимых GPU AMD через HIP/ROCm.
Для режима «Плотное облако — AMD HIP» необходим **отдельно собранный COLMAP с
HIP**, совместимый с установленными драйвером, ОС и моделью карты. Стандартный
пакет `pycolmap` из `requirements.txt` работает на CPU и сам по себе HIP не
добавляет; стандартный Windows-архив COLMAP без CUDA также не является HIP-сборкой.
Инструкция по сборке: [COLMAP: Installation](https://colmap.github.io/install.html).

Этот режим вызывает `patch_match_stereo` и `stereo_fusion` внешней программы
COLMAP после CPU-этапа. Он **не проверен на реальном AMD GPU**; не заявляется
совместимость с конкретной картой или Windows-сборкой. Обычный CPU-режим остаётся
отдельным вариантом. Не подменяйте исходную сборку произвольным сторонним бинарным
файлом без проверки источника и совместимости.

## Фотографии

Для первого опыта снимите один неподвижный объект или небольшую комнату с разных
положений камеры, обеспечив сильное перекрытие соседних кадров. Избегайте
бликов, стекла, однотонных стен, смаза и резкой смены освещения. Успех зависит от
съёмки; даже корректный запуск может не найти достаточно общих точек.

## Командная строка

Новая папка результата должна находиться вне папки фотографий:

```sh
python python/research/photo_to_cloud/reconstruct.py --images /path/to/photos --output /path/to/new-result --mode sparse-cpu
python python/research/photo_to_cloud/reconstruct.py --images /path/to/photos --output /path/to/new-result --mode dense-cpu --openmvs-dir /path/to/openmvs
```

Для исследования HIP можно выбрать `--mode dense-amd --colmap /path/to/hip/colmap`.
Ошибки возвращают ненулевой код; проверяйте журнал и `report.json`.

Для Radeon RX 7900 XTX целевая архитектура HIP — `gfx1100`. Официальная поддержка
HIP SDK для этой карты не означает, что любая сборка COLMAP автоматически будет
работать: версии ОС, драйвера и ROCm/HIP должны совпадать, а реальная проверка
на этой карте остаётся открытой.
